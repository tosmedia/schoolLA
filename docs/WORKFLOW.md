# WORKFLOW — как Claude работает над SchoolLA

Этот регламент обязателен для каждого чата. Цель: никогда не терять контекст
и не отправлять в GitHub то, что не проверено.

## Где лежит состояние проекта

Четыре файла. Они хранятся в трёх местах, и их содержимое везде одинаковое:

| Файл | Что в нём | Как меняется |
|---|---|---|
| `docs/STATUS.md` | Текущее состояние: что на live, на каком коммите `main`, что сломано или не залито, следующие шаги | Переписывается под текущую правду в конце каждой задачи |
| `docs/JOURNAL.md` | Хронологический журнал: дата, что сделано, почему, коммит | Только дописывается снизу, старое не правится |
| `docs/PROJECT_CONTEXT.md` | Что за проект, решения по бренду и контенту, технические ограничения | Правится, когда меняется решение или ограничение |
| `docs/WORKFLOW.md` | Этот регламент | Правится только по просьбе Эдварда |

Три места хранения:
1. **GitHub** `tosmedia/schoolLA`, папка `docs/`. Это главный источник.
2. **Проект Claude «SchoolLA»**: `claude/STATUS.md`, `claude/JOURNAL.md`, `claude/PROJECT_CONTEXT.md`, `claude/WORKFLOW.md`. Их видят все чаты проекта.
3. **Папка SchoolLA на Маке**: `docs/` и `tools/`.

Проверки сайта лежат в `tools/check_site.py`.

## Шаги на каждой задаче

### 1. Прочитать состояние
- Прочитать `STATUS.md` и последние записи `JOURNAL.md`: сначала в проекте Claude, при сомнении в GitHub.
- Сверить, что последний коммит `main` (`list_commits`) совпадает с тем, что записан в STATUS. Если не совпадает, кто-то пушил мимо журнала: сначала разобраться, что изменилось, и записать это.
- Если подключена папка SchoolLA на Маке, сверить её `index.html` с репо по blob-sha (`git hash-object` или python), чтобы понимать, какая версия лежит у Эдварда.
- VM на Маке и облачный контейнер пересоздаются между сессиями. Ничего не ждать от старых клонов в `/tmp`.

### 2. Найти причину, а не симптом
- На «не работает» не верить догадкам: воспроизвести. Сделать grep по `index.html`, открыть live, отрендерить страницу.
- Рендер из контейнера: Google Fonts оттуда заблокирован. Шрифты брать из npm (`@fontsource/*`), конвертировать woff2→ttf через fontTools и подставлять через @font-face.

### 3. Править
- Править `index.html` в папке на Маке через `device_bash`: `sed -i` или python read-modify-write. Никогда не перепечатывать файл из вывода инструмента.
- Одна задача за раз, без попутных «улучшений». Эдвард: «не делать лишних изменений без запроса».

### 4. Тесты
- На каждую починку добавить в `tools/check_site.py` проверку, которая ловит именно эту поломку.
- Убедиться, что новая проверка падает на сломанной версии: подставить поломку и прогнать.
- Прогнать весь набор: `python3 tools/check_site.py`. Количество проверок и результат записать в STATUS.

### 5. Записать
Порядок: `STATUS.md`, затем `JOURNAL.md`, затем при необходимости `PROJECT_CONTEXT.md`. Потом зеркалировать во все три места.

### 6. Доставить в GitHub и сверить
- **Текстовые файлы** (`*.md`, `index.html`, `*.py`) пушить через GitHub-коннектор (`push_files`, он авторизован как `tosmedia`). Это работает прямо из облака.
- **Бинарные файлы** (jpg/png/webp) через коннектор не проходят, а `git push` из облака режет прокси. Два варианта:
  - собрать патч (`git format-patch`), положить файл в папку SchoolLA и дать Эдварду команды для `git am` и push в его клоне. Команды давать по одной, без `&&`;
  - либо пушить с VM на Маке (`device_bash`) с токеном, который Эдвард даёт на один раз. Токен нигде не сохранять.
- **Сверка после пуша, обязательно.** blob-sha каждого файла в GitHub (`get_file_contents`) должен совпасть с `git hash-object` локального файла. Тогда в GitHub лежит ровно то, что тестировалось.
- После пуша `index.html` открыть https://tosmedia.github.io/schoolLA/: Pages пересобирается меньше чем за минуту.

### 7. Отчитаться
Коротко: что было сломано, почему, что теперь, и 2–3 действия, которые остались за Эдвардом.

## Как Эдвард предпочитает работать
- Общается по-русски, часто голосом. Отвечать по-русски.
- Команды в терминал вставляет сам: нужны чёткие пошаговые инструкции, что куда вставлять.
- Команды давать по одной, без сцепления через `&&`.
- Не делать лишних изменений в его файлах и репозиториях без запроса.
- Удалять что-либо в его папках только с явного разрешения.
